The `rewire` CLI exposes all bridge functionality through a set of focused subcommands. Most accept a `--config` flag pointing to a JSON5 config file; if you omit it, Rewire reads `~/.config/rewire/config.json5` automatically. Verbosity is per-subcommand rather than global — `record`, `play`, and `serve` accept `--log-level`, which outranks the `RUST_LOG` environment variable, which in turn outranks the `log_level` config key. All other subcommands fall back to the environment variable and the config key only.

---

## Global Flags

These flags are accepted before any subcommand.

| Flag | Short | Description | Default |
|---|---|---|---|
| `--version` | `-v`, `-V` | Print the version and exit | — |
| `--help` | `-h` | Print help | — |
| `--color <WHEN>` | — | When to colorize output (`auto`, `always`, `never`) | `auto` |

<Tip>
  For a full version table that covers the viewer and all dependencies, use [`rewire version`](#rewire-version).

## `rewire record`

Subscribe to ROS 2 topics and stream data to Rerun.

```bash
rewire record [OPTIONS]
```

| Flag | Short | Description | Default |
|---|---|---|---|
| `--all` | `-a` | Subscribe to all discovered topics — already the default when nothing else selects any | _(implied)_ |
| `--topics <TOPICS>` | `-t` | Subscribe to specific topics | — |
| `--exclude <EXCLUDE>` | `-e` | Exclude topics by glob pattern | — |
| `--connect <ADDRESS>` | — | Stream to a remote viewer or relay (shorthand accepted) | — |
| `--save [STEM]` | — | Save each recording to `<stem>_<recording_id>.rrd`, _and_ stream live; bare flag uses `<app_id>_<timestamp>` as the stem | — |
| `--save-session` | — | With `--save`, append every recording of the run to one `<stem>_<timestamp>.rrd` | `false` |
| `--no-live` | — | Save with no live half: no port probe, no connect, no viewer spawn. Requires `--save`; conflicts with `--connect` | `false` |
| `--flush-tick-ms <MS>` | — | How often the live stream is flushed to the viewer, in milliseconds; ignored with `--no-live` | `8` |
| `--scalar-flush-tick-ms <MS>` | — | Hold plot-class chunks (scalars, series styling, text logs) this long and forward them merged into one chunk per entity; `0` disables | `150` |
| `--live-queue-mib <MIB>` | — | Byte budget for the live stream's never-blocking queue; a slow consumer costs counted drops of the oldest data instead of stalling the bridge. `0` disables the bound | `64` |
| `--config <PATH>` | — | Load JSON5 config file | `~/.config/rewire/config.json5` |
| `--mappings <PATH>` | — | Load custom message mappings | — |
| `--transport <all\|dds\|zenoh>` | — | Wire transports to start | `all` |
| `--domain-id <ID>` | — | ROS 2 domain ID | `$ROS_DOMAIN_ID` or `0` |
| `--diagnostics` | — | Enable per-topic diagnostics | `false` |
| `--ws` | — | Enable WebSocket server | `false` |
| `--ws-port <PORT>` | — | WebSocket server port | `9090` |
| `--secure` | — | Require bearer token authentication for WebSocket | `false` |
| `--zenoh-connect <ENDPOINTS>` | — | Zenoh router endpoints (e.g. `tcp/192.168.1.100:7447`) | — |
| `--throttle <TOPIC=HZ>` | — | Cap a topic's bridged rate (repeatable) | — |
| `--discovery-timeout <SECS>` | — | Seconds to block on discovery before subscribing; unset means subscription is eager | _(unset)_ |
| `--queue-depth <N>` | — | Message queue depth | — |
| `--latched-depth <N>` | — | History depth for latched (transient-local) topics like `/tf_static` | — |
| `--log-level <FILTER>` | — | Log filter directives, e.g. `bridge=debug` or `info,iris=trace` | `$RUST_LOG` or the `log_level` config key |

<Note>
  Running `rewire record` with no topic flags subscribes to everything on the graph. Pass `--all` explicitly only to override an `include` list in the config file; `--exclude` narrows either.
</Note>

<Note>
  `--save` takes a filename _stem_, not a full path with extension — a `.rrd` suffix on the stem is ignored. Rewire completes the name so that concurrent or successive recordings never overwrite each other. A `rewire log` swap rotates to a fresh file automatically.
</Note>

<Note>
  Saving also streams: a `--save` run resolves the same live half as a flagless one, connecting to whatever already holds port `9876` or starting the embedded relay and viewer, so you can watch what you are capturing. Add `--no-live` for file-only output on measurement runs or machines with no display.
</Note>

## `rewire play`

Stream a recorded MCAP bag to a viewer, or convert it to an RRD file.

```bash
rewire play <INPUT> [OPTIONS]
```

| Flag | Short | Description | Default |
|---|---|---|---|
| `--save <PATH>` | `-o` | Convert the bag to this RRD file instead of streaming (unpaced) | — |
| `--connect <ADDRESS>` | — | Stream to a running relay or Rerun viewer | — |
| `--rate <RATE>` | — | Playback rate multiplier (streaming mode only) | `1.0` |
| `--flush-tick-ms <MS>` | — | How often the live stream is flushed to the viewer, in milliseconds (streaming mode only) | `8` |
| `--scalar-flush-tick-ms <MS>` | — | Hold plot-class chunks this long and forward them merged into one chunk per entity; `0` disables (streaming mode only) | `150` |
| `--live-queue-mib <MIB>` | — | Byte budget for the live stream's never-blocking queue; `0` disables the bound (streaming mode only) | `64` |
| `--topics <TOPICS>` | `-t` | Play only these topics | _(all topics)_ |
| `--exclude <EXCLUDE>` | `-e` | Exclude topics by glob pattern | — |
| `--throttle <TOPIC=HZ>` | — | Cap a topic's rate in bag time (repeatable) | — |
| `--mappings <PATH>` | — | Load custom message mappings | — |
| `--config <PATH>` | — | Load JSON5 config file | `~/.config/rewire/config.json5` |
| `--log-level <FILTER>` | — | Log filter directives, e.g. `bridge=debug` or `info,iris=trace` | `$RUST_LOG` or the `log_level` config key |

<Warning>
  `--save` and `--connect` are mutually exclusive. Conversion writes exactly the path you name and never connects to a viewer.
</Warning>

## `rewire serve`

Run a standalone headless relay that bridges stream to and viewers connect through.

```bash
rewire serve [OPTIONS]
```

| Flag | Description | Default |
|---|---|---|
| `--bind <ADDR>` | Address to bind the gRPC listener on | `0.0.0.0` |
| `--port <PORT>` | gRPC listen port | `9876` |
| `--memory-limit <LIMIT>` | Buffered history limit before the oldest data is dropped (`64MiB`, `500MB`, `50%`, `unlimited`). The default keeps essentially no temporal history | `1MiB` |
| `--cors-allowed-origin <PATTERN>` | Additional origin allowed for cross-origin gRPC-web requests (repeatable) | — |
| `--save [STEM]` | Archive relay traffic to `<stem>_<timestamp>.rrd`; bare flag uses `rewire-relay` as the stem | — |
| `--config <PATH>` | Load JSON5 config file (`serve` section) | `~/.config/rewire/config.json5` |
| `--log-level <FILTER>` | Log filter directives, e.g. `bridge=debug` or `info,iris=trace` | `$RUST_LOG` or the `log_level` config key |

## `rewire doctor`

Run environment health checks.

```bash
rewire doctor [OPTIONS]
```

| Flag | Description | Default |
|---|---|---|
| `--transport <all\|dds\|zenoh>` | Wire transports to start | `all` |
| `--domain-id <ID>` | ROS 2 domain ID | `$ROS_DOMAIN_ID` or `0` |
| `--zenoh-connect <ENDPOINTS>` | Zenoh router endpoints | — |
| `--discovery-timeout <SECS>` | Seconds to wait for discovery before reporting | `2` |
| `--config <PATH>` | Load JSON5 config file | `~/.config/rewire/config.json5` |

`rewire doctor` runs the following checks:

- **DDS middleware availability** — confirms the DDS stack is reachable
- **Zenoh connectivity** — verifies the Zenoh transport can connect
- **Network configuration** — inspects interface and routing settings
- **Converter readiness** — ensures message type converters are loaded
- **System limits** — warns when Linux `net.core.rmem_max` is below the receive buffer Rewire requests; the default 208 KB silently drops fragmented images and point clouds under load

## `rewire upgrade`

Update Rewire to the latest version.

```bash
rewire upgrade [OPTIONS]
```

| Flag | Description | Default |
|---|---|---|
| `--relocate` | Move the install into `~/.local/bin` so upgrades stop needing `sudo` | _(upgrades in place)_ |

<Note>
  Both binaries are upgraded together. The bridge installs the `rewire-viewer` bundled with the release it fetches, keeping the pair matched. A viewer released independently since your last upgrade is also brought up to date.
</Note>

<Note>
  Upgrading replaces a binary by renaming over it, which requires write permission on the install directory rather than on the file itself. An install in a directory you own — the install script's `~/.local/bin` default — needs no elevated rights. A root-owned install such as `/usr/local/bin` does, and the upgrade says so before it downloads anything.
</Note>

<Warning>
  Passing `--relocate` copies both binaries into `~/.local/bin`, updates them, and clears the originals once the new location is reachable on `PATH`. Run it **without** `sudo` — under `sudo`, `HOME` and `PATH` belong to root, so the check guarding the deletion answers for the wrong environment.
</Warning>

<Info>
  `rewire upgrade` only works for installs via the install script. If you installed via pixi or apt, use your package manager to update: `pixi update` or `apt upgrade`.
</Info>

## `rewire uninstall`

Remove Rewire and the bundled viewer from the directory they were installed into.

```bash
rewire uninstall [OPTIONS]
```

| Flag | Short | Description | Default |
|---|---|---|---|
| `--purge` | — | Remove the config file and logs as well | _(both kept)_ |
| `--yes` | `-y` | Skip the confirmation prompt | `false` |

Both binaries are removed, along with the version cache kept beside them. The config file and logs are left in place by default, so a reinstall picks up the settings you already had. Pass `--purge` to remove those too.

<Note>
  The command prints everything it is about to delete and waits for confirmation. If the install directory is not writable, it says so before the prompt — while you can still answer no — rather than failing partway through. With no terminal to ask on, it stops instead of assuming an answer, so unattended runs need `--yes`.
</Note>

<Warning>
  Only standalone installs are removed. If a package manager owns the install, `rewire uninstall` refuses and names the correct command to run instead — `sudo apt remove rewire`, `pixi global uninstall rewire`, or `brew uninstall rewire`. A binary running from a `cargo` build is also refused, with `cargo clean` as the answer.
</Warning>

## `rewire mappings generate`

Inspect discovered topics and generate a JSON5 custom mappings template. Rewire spawns a type resolver automatically and waits for custom schemas to resolve before writing the output.

```bash
rewire mappings generate <TOPICS>... [OPTIONS]
```

| Flag | Short | Description | Default |
|---|---|---|---|
| `<TOPICS>...` | — | Topic names to generate templates for (required) | — |
| `--output <PATH>` | `-o` | Write output to a file instead of stdout | _(prints to stdout)_ |
| `--transport <all\|dds\|zenoh>` | — | Wire transports to start | `all` |
| `--domain-id <ID>` | — | ROS 2 domain ID | `$ROS_DOMAIN_ID` or `0` |
| `--zenoh-connect <ENDPOINTS>` | — | Zenoh router endpoints | — |
| `--discovery-timeout <SECS>` | — | Seconds to wait for discovery | `5` |
| `--resolve-timeout <SECS>` | — | Seconds to wait for schema resolution via `get_type_description` (Jazzy+) | `15` |

<Tip>
  Discovery settings are read from the config file at its default location, so a `transport` or `domain_id` set there applies here exactly as it does to `rewire record`.
</Tip>
