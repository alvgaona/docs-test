Rewire ships 74 built-in mappings from ROS 2 message types to Rerun archetypes — these work automatically with no configuration. Rewire aims to align its mappings with the conventions Rerun uses for MCAP ingestion, so data recorded with Rewire should look familiar if you've used Rerun's built-in MCAP loader. That said, full parity is not guaranteed — some mappings may differ where Rewire optimizes for live streaming or supports ROS 2-specific semantics that don't have a direct MCAP equivalent.

<Note>
Run `rewire types` at any time to see the current list of supported message types and their corresponding Rerun archetypes for your installed version.
</Note>

<Note>
Several types log their reported uncertainty as an extra `Scalars` series alongside the primary measurement:

- `Temperature`, `FluidPressure`, `RelativeHumidity`, `Illuminance`, `Range` — variance
- `Imu` — orientation, angular velocity, and linear acceleration covariance diagonals
- `Odometry` — twist covariance diagonal
</Note>

## example\_interfaces

`std_msgs/String` on a topic ending in `/robot_description` is loaded as a URDF instead of a plain text document. This produces `Asset3D`, `Transform3D`, `CoordinateFrame`, and `InstancePoses3D` archetypes. See [URDF Loading](/urdf-tf/urdf) for details.
</Note>
