Rewire supports both DDS and Zenoh simultaneously. By default it bridges both transports at once, so you rarely need to choose — but understanding the trade-offs helps you tune Rewire for your specific deployment.

You don't have to pick one. If your network has nodes on both DDS and Zenoh, Rewire discovers and subscribes to topics on both transports at the same time without any extra configuration.

## DDS vs Zenoh

<Tabs>
  <Tab title="DDS">
    DDS (Data Distribution Service) is the default middleware for ROS 2. Most ROS 2 installations use either CycloneDDS or FastDDS.

    **When to use DDS:**

    - You're running a standard ROS 2 setup with the default middleware
    - All nodes are on the same local network or subnet
    - You need zero configuration — DDS discovery works out of the box on a LAN
    - You're using CycloneDDS or FastDDS

    **Considerations:**

    - DDS discovery uses multicast, which may not work across subnets or VPNs without extra configuration
    - Large-scale deployments with many nodes and topics can generate significant discovery traffic
    - Some cloud and container environments block multicast by default
  </Tab>
  <Tab title="Zenoh">
    Zenoh is a newer protocol adopted by ROS 2 via `rmw_zenoh`. It's designed for wide-area networks and resource-constrained environments.

    **When to use Zenoh:**

    - Your ROS 2 nodes use `rmw_zenoh` as the middleware
    - You need to bridge across subnets, VPNs, or cloud environments
    - You want lower discovery overhead in large-scale deployments
    - You're running a fleet of robots that need to communicate across networks

    **Considerations:**

    - Requires `rmw_zenoh` or `zenoh-plugin-ros2dds` on the ROS 2 side
    - Less mature than DDS in the ROS 2 ecosystem
  </Tab>
</Tabs>

## Mixed Networks

Rewire discovers topics on both DDS and Zenoh at the same time. If a topic is available on both transports, Rewire subscribes via whichever transport discovered it first. No manual assignment is needed — just run `rewire record` and Rewire handles the rest.

## Choosing Transports

By default Rewire starts both transports, which is the right choice for almost every setup. It costs a Zenoh session that finds nothing when there is no router, and it means a node that moves between middlewares requires no change on the Rewire side.

Narrow it with `--transport` when you know only one transport is in play:

<CodeGroup>
  ```bash CLI
  rewire record --transport dds      # DDS only
  rewire record --transport zenoh    # Zenoh only
  rewire record --transport all      # both (the default)
  ```

  ```json5 JSON5 config
  {
      transport: "dds",
  }
  ```
</CodeGroup>

The `--transport` flag is shared by `rewire record`, `rewire doctor`, and `rewire mappings generate`. A CLI flag always takes precedence over the config file key.

<Tip>
  The case for narrowing is a DDS-only deployment: starting Zenoh there carries
  a session and a background dial loop against a router that was never meant to
  exist. Picking `zenoh` likewise skips DDS discovery traffic on a fleet that
  has moved to `rmw_zenoh`.
</Tip>

## Configuration

### DDS Domain ID

Set the DDS domain ID to match your ROS 2 network. The default is `0`.

```bash
rewire record --domain-id 42
```

Alternatively, set the `ROS_DOMAIN_ID` environment variable — Rewire respects it automatically.

### Zenoh Router

By default, Rewire dials `tcp/localhost:7447`, the port where the `rmw_zenoh` router listens. If your Zenoh nodes are behind a router at a different address, pass the endpoint via the CLI or config file:

<CodeGroup>
  ```bash CLI
  rewire record --zenoh-connect tcp/192.168.1.100:7447
  ```

  ```json5 JSON5 config
  {
      zenoh: {
          connect: ["tcp/192.168.1.100:7447"],
      },
  }
  ```
</CodeGroup>

<Note>
  Set `zenoh.multicast_scouting: true` to also scout for peers over multicast,
  in addition to dialing the endpoints above. It is off by default because the
  `rmw_zenoh` router runs with scouting disabled — enabling it here will not
  find an `rmw_zenoh` router.
</Note>
